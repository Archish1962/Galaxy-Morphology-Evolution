# Galaxy Morphology Evolution — Dashboard Explanation & Study Guide

This document breaks down every feature, interactive element, and technical detail within the Streamlit application (`galaxy_app.py`). Use this to explain how the app works, what every slider does, and how it ties back to the actual Machine Learning models under the hood.

---

## 🏗️ Overall Architecture

The application is built using **Streamlit**, a Python framework for creating data apps. 
- **Navigation:** It uses a sidebar with radio buttons (`st.radio`) to switch between six distinct pages.
- **Data Caching:** To make the app run fast, it uses the `@st.cache_data` decorator to load large CSV files (like the 47,000-row master dataset) only once.
- **Model Caching:** It uses `@st.cache_resource` to load the PyTorch models into memory once, so inference is instant rather than reloading the ~11M parameter model every time you click "Classify".

## 1. Home Page (`Home`)
**Purpose:** An executive summary of the project pipeline and scientific findings.
- **Visuals:** Uses HTML/CSS styled "hero" titles and Metric cards (`st.metric`) to show high-level project stats (e.g., 47,089 Galaxies, 4 Classes, 78.8% Best Accuracy).
- **Explanation:** It summarizes the 4 project phases (Baseline, Multimodal, Drift, Visualisation) and the 4 key scientific findings regarding how galaxy morphology drifts across redshift.

---

## 2. Exploratory Data Analysis (`EDA`)
**Purpose:** To show the raw data distributions before any modelling was done.
- **Interactive Element (Tabs):** Uses `st.tabs()` to organize 5 different data views.
  - **Tab 1: Class Distribution:** Uses Plotly (`px.bar`) to show how many galaxies belong to each class (disk, edge_on, smooth, spiral), highlighting the class imbalance.
  - **Tab 2: Redshift Distribution:** A histogram showing how far away the galaxies are. We see a peak near $z \approx 0.08$.
  - **Tab 3: Color vs Redshift:** A scatter plot of $u-r$ color index vs. redshift. It shows the "red sequence" (smooth, older, redder galaxies) and the "blue cloud" (spiral/disk, star-forming, bluer).
  - **Tab 4: Structural Features:** A histogram of `fracdev_r` (how much the galaxy follows a de Vaucouleurs profile vs. an exponential disk profile).
  - **Tab 5: Galaxy Browser:** An interactive dropdown (`st.selectbox`) where you choose a class, and a slider (`st.slider`) to choose how many images to display. It then fetches real SDSS images from the `images_gz2/` folder.

---

## 3. Model Performance (`Model Performance`)
**Purpose:** Proof that the models successfully learned the morphology.
- **Summary Table:** A Pandas DataFrame styled with `st.dataframe` showing Test Accuracy and F1 scores. It proves the Multimodal ResNet-18 model is the best (78.5% Acc).
- **Tabs (Baselines vs Multimodal):** Separates the pure-image networks from the fusion networks.
- **Static Images:** Loads the output `.png` files generated by our training scripts (e.g., `training_curves.png` and `confusion_matrix.png`) using `st.image()`.

---

## 4. Centroid Drift Analysis (`Drift Analysis`)
**Purpose:** The core scientific finding. Shows how the abstract concept of a class changes as redshift increases.
- **Interactive Dropdown (`backbone`):** A selectbox to toggle between the embeddings of the `resnet18` model and the `efficientnet_b0` model.
- **Visualisation 1 (Populations):** A Plotly bar chart showing the statistical validity of each bin. Smooth galaxies dominate at high redshift.
- **Visualisation 2 (Euclidean Drift):** A grouped Plotly bar chart showing the magnitude of shift from $low\_z \rightarrow mid\_z$ across classes. You can explain that "Disk" drifts the most because resolution loss causes the model to confuse it with "Smooth".

---

## 5. Galaxy Embedding Map (`Galaxy Map`)
**Purpose:** A 2D topographical map of the 256-dimensional "brain" of our neural network.
- **Dropdowns:** Select `Method` (UMAP, t-SNE) and `Backbone`.
- **Slider (`Points to show`):** Ranging from 1,000 to 20,000. Less points load faster, more points show denser structure.
- **Plotly Scatter (`px.scatter`):** A massive interactive graph.
- **The "Magic" Feature (`on_select`):** 
  - Streamlit captures "click" events on the Plotly map. 
  - When a user clicks a dot, the app reads the `customdata` associated with that dot (which is the SDSS `dr7objid`).
  - It then queries the master CSV to find the exact row, pulls the `jpg` from the folder, and displays the image below the map. 
  - **Why this matters:** It visually proves that the abstract clusters represent physical, correct features. Clicking the far left of a cluster yields a pure spiral, while the right yields a tight smooth galaxy.

## 6. Live Galaxy Classifier (`Live Classifier`)
**Purpose:** A real-time inference sandbox. This allows the user to test the actual trained PyTorch model.

### 🖼️ Input Block
- **Dropdown:** Select the `ResNet18` or `EfficientNet-B0` architecture.
- **Radio Button:** Choose between uploading a local image or randomly picking from the dataset.
- **Pick Random Galaxy Button:** If selected, it queries the master CSV, randomly samples one row, and populates the sliders with the *real ground-truth* data for that galaxy.

### 🔢 The Six Metadata Sliders
If we are testing the **Multimodal** network, we must feed it both an image AND 6 metadata features. The sliders allow you to manipulate these features to see how they impact the neural network's final decision:
1. **Redshift ($z$) [0.0 - 0.5]:** How far away the galaxy is.
2. **Color u-r [0.0 - 4.0]:** The ultraviolet minus red color index. (Higher = red/older).
3. **Color g-i [0.0 - 4.0]:** The green minus infrared color index.
4. **FRACDEV_R [0.0 - 1.0]:** The fraction of light fit by a de Vaucouleurs profile (bulge) vs an exponential profile (disk). A value near 1.0 means it looks like an elliptical (smooth) galaxy; 0.0 means it's a flat disk.
5. **PETROR50_R_KPC [0.0 - 50.0]:** The physical size/radius of the galaxy in kiloparsecs.
6. **MU50_R [17.0 - 28.0]:** Peak surface brightness.

### 🔮 The "Classify" Button Action
When you click **"Classify This Galaxy"**:
1. A spinner appears (`st.spinner`).
2. The PyTorch model is loaded from `checkpoints/multimodal_{backbone}.pth`.
3. The image is converted into a PyTorch tensor, resized to `224x224`, and normalized.
4. The 6 slider values are combined into a tensor and normalized using the *exact training mean and standard deviation* (loaded from `metadata_stats.pth`).
5. Both tensors are passed through the network: `logits = model(img_tensor, metadata_tensor)`.
6. `Softmax` is applied to convert the logits into confidence percentages.

### 📊 The Output
- Displays the predicted class with a large icon (e.g., S for Spiral, E for Edge-on).
- Shows the confidence percentage (e.g., 98.4%).
- Plots a horizontal bar chart of probabilities across all 4 classes.
- If you picked a random galaxy, the app automatically checks the prediction against the **ground truth** and displays a green `success` or red `error` banner.

## 💡 Quick Tips for Explaining it during your Exam:
*   **Emphasize "Real-time AI":** Mention that the Live Classifier isn't a pre-recorded mock-up. It is doing forward-pass matrix multiplication on the PyTorch model locally using the inputs provided by the sliders.
*   **Explain Multimodal Context:** Point out the sliders. Explain that if you take an image of a Spiral galaxy, but force the `fracdev_r` slider to `1.0` (which implies a massive elliptical bulge), the network's confidence will plummet because the visual image and the metadata contradict each other. That proves the model uses both modalities!
*   **Explain the Map Interaction:** The ability to click a dot on the 2D layout and see the SDSS image proves that the network has successfully learned a "latent space representation" of morphology without any hard-coded rules.
